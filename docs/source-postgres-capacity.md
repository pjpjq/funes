# PostgreSQL B＋非重复 shadow：同样本容量报告

**2026-09-22，供 review；未修改生产 HF/PG，未全量导入。**

## 1. 结论与范围

本次正式迁移器的隔离 10,000 行测试，外推 **3,590,437 行 =
17.087903 GiB/单副本**，比 20 GiB 静态目标低 **2.912097 GiB**。
这是关系文件静态容量估算，不是“20 GiB 磁盘可安全容纳运行峰值”的保证。
WAL、备份、临时维护空间、未来增长及其他 schema **未计入**。
没有乘以 3 replicas；三个完整副本的关系文件合计约 51.263709 GiB，
但本次目标和以下表格始终是**单副本**。

采用 **B＋仅不同的 retrieval_text**，不是直接照搬旧 B 数字：
旧 B 没有保存 retrieval_text，本版必须保留与 raw 不同的 shadow。
PG 不创建 stored/generated tsvector、GIN、GiST、trigram 或 pgvector，
也不提供大表内容扫描 fallback。`search_identifiers` 保留为数据字段，
不在 PG 建内容检索索引。

| 方案 | 单副本 GiB | 口径 |
|---|---:|---|
| 旧 A | 12.239321 | 基础字段和必要索引；前次同样本测量 |
| 旧 B | 15.573032 | A＋search_identifiers；不保存 retrieval_text |
| 旧 C | 42.300246 | B＋stored tsvector＋GIN |
| 旧 D | 48.795093 | 原完整 schema |
| 本次 v2 | **17.087903** | B＋仅不同的 retrieval shadow，正式迁移器 COPY/finalize |

旧 C−B 为 **26.727214 GiB**。本次比旧 D 减少 **31.707190 GiB（64.98%）**。
旧 A/B/C/D 为上一轮已给出的历史测量基线，本次没有再重复创建四套派生索引。
物理行宽/TOAST 分配有非线性影响，不把“省下的字符串字节数”当成磁盘节省量。

## 3. heap / TOAST / B-tree / total

| 分项 | 10k 实测 bytes | 3,590,437 行外推 GiB |
|---|---:|---:|
| memories heap main | 19,922,944 | 6.661944 |
| TOAST（含其自带索引和 forks） | 28,966,912 | 9.686115 |
| memories B-tree（不重复包含 TOAST 索引） | 2,187,264 | 0.731389 |
| memories 其他 forks | 24,576 | 0.008218 |
| **memories total** | **51,101,696** | **17.087666** |
| 固定附表、迁移 ledger、sequence | 253,952 | 0.000237 |
| **总计** | **51,355,648** | **17.087903** |

TOAST 进一步拆开：数据 main **28,508,160**、自己的 B-tree
**434,176**、TOAST 其他 forks **24,576 bytes**。
上表 TOAST 已包含这三项，不能再额外相加。

```text
factor = 3,590,437 / 10,000 = 359.0437
memories = (19,922,944 + 28,966,912 + 2,187,264 + 24,576)
         = 51,101,696 bytes
single_replica_GiB
  = (51,101,696 × 359.0437 + 253,952) / 1,073,741,824
  = 17.087902836608887
20 GiB margin = 2.912097163391113
```

仅 memories 随记录数放大；固定附表 **不乘 359.0437**。
这也不预测以后翻译缓存或迁移 ledger 的增长量。
采样占全量 0.2785%，未给统计置信区间；实际全量分布、更新膨胀、
TOAST 压缩和索引填充率可能偏离样本，应在未来获准导入时持续测量。

测量口径使用 `pg_relation_size`、`pg_table_size`、`pg_indexes_size`、
`pg_total_relation_size`。`pg_table_size` **已含 TOAST 和 forks**，
因此没有将它再与 TOAST 相加。主表 total 单独放大，附表各自 total
相加，不把索引清单再加一次。
官方定义：`https://www.postgresql.org/docs/16/functions-admin.html`。

## 4. 实际 v2 schema

下列为 `service/postgres.py` 的 memories DDL。只保留原始数据、来源和
运行 checkpoint 必需字段；没有文本检索向量列或 embedding 列。

```sql
CREATE TABLE IF NOT EXISTS memories (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    source_identity TEXT NOT NULL UNIQUE,
    source_version TEXT NOT NULL DEFAULT '',
    raw_text TEXT NOT NULL, retrieval_text TEXT,
    search_identifiers TEXT NOT NULL DEFAULT '',
    metadata_json TEXT NOT NULL DEFAULT '{}',
    source_metadata_clock_json TEXT NOT NULL DEFAULT '{}',
    source_agent TEXT, source_type TEXT, device_id TEXT, project TEXT,
    repo TEXT, worktree TEXT, session_id TEXT, message_id TEXT, role TEXT,
    timestamp TEXT, source_path TEXT, content_hash TEXT NOT NULL,
    ingested_at TEXT NOT NULL, updated_at TEXT NOT NULL, retrieval_updated_at TEXT,
    content_type TEXT, source_missing INTEGER NOT NULL DEFAULT 0,
    agent_type TEXT, parent_session_id TEXT, agent_id TEXT,
    translation_hash TEXT, translation_version TEXT, translation_status TEXT,
    native_index_version TEXT, native_index_status TEXT, native_index_profile TEXT,
    native_index_memory TEXT, native_indexed_at TEXT, native_index_error TEXT,
    native_index_pending INTEGER NOT NULL DEFAULT 1,
    retrieval_generation BIGINT NOT NULL DEFAULT 0,
    native_generation BIGINT NOT NULL DEFAULT 0,
    embedding_generation BIGINT NOT NULL DEFAULT 0
);
```

以下为测量时 `pg_indexes.indexdef` 的**全部索引**，仅移除随机测试
schema 前缀。PK/UNIQUE 对应的 CREATE UNIQUE INDEX 只是展示实际产物，
不要在建表后重复手工执行。memories 为 2 个约束索引＋7 个业务 B-tree；
其余为附表主键索引。

```sql
CREATE UNIQUE INDEX funes_schema_state_pkey ON funes_schema_state USING btree (id);
CREATE UNIQUE INDEX funes_source_migration_pkey ON funes_source_migration USING btree (id);
CREATE INDEX memories_canonical_pending_idx ON memories USING btree ((
CASE
    WHEN (native_index_status = 'retry'::text) THEN 1
    ELSE 0
END), COALESCE(retrieval_updated_at, updated_at), id) WHERE (native_index_pending = 1);
CREATE INDEX memories_embedding_generation_idx ON memories USING btree (embedding_generation);
CREATE INDEX memories_native_generation_idx ON memories USING btree (native_generation);
CREATE UNIQUE INDEX memories_pkey ON memories USING btree (id);
CREATE INDEX memories_retrieval_generation_idx ON memories USING btree (retrieval_generation);
CREATE INDEX memories_source_agent_role_idx ON memories USING btree (source_agent, role);
CREATE INDEX memories_source_agent_type_idx ON memories USING btree (source_agent, source_type);
CREATE UNIQUE INDEX memories_source_identity_key ON memories USING btree (source_identity);
CREATE INDEX memories_translation_pending_idx ON memories USING btree (updated_at, id) WHERE ((translation_status = 'pending_provider'::text) AND (COALESCE(native_index_status, ''::text) <> 'waiting_durability'::text));
CREATE UNIQUE INDEX reindex_controls_pkey ON reindex_controls USING btree (generation);
CREATE UNIQUE INDEX sync_state_pkey ON sync_state USING btree (id);
CREATE UNIQUE INDEX translation_cache_pkey ON translation_cache USING btree (query);
```

## 5. NULL shadow 的数据契约

1. 仅当字符串逐字相等时，写入 `retrieval_text=NULL`；原始 raw 永不改写。
2. 读取、原文回填、native handoff、snapshot 和迁移摘要使用逻辑值
   `COALESCE(retrieval_text, raw_text)`；只有 SQL NULL 表示复用 raw。
3. 导入的空字符串 `''` 不等于 NULL，保持原值；NUL/转义标记使用可逆
   PostgreSQL TEXT codec，且只解码一次。
4. COPY 关闭计数 triggers 时由迁移器明确压缩；在线写入由 BEFORE
   trigger 维护；纯物理压缩不会推进 native revision。
5. 翻译结果持久化失败后的重排队使用逻辑 shadow CAS，原始 raw 计算
   identifiers，不调用 SQLite 函数，陈旧版本/hash/generation 不覆盖新结果。

同样本有 **4,002 行**物理 NULL，省去的相同 text 在 PG 编码后合计
**9,240,285 bytes**；非 NULL shadow 为 **8,033,006 bytes**。
这是编码后 TEXT 的 octet_length，不等于压缩后的磁盘占用，
也不与未编码 SQLite 字节直接做减法：样本含 5 处 NUL text 字段。

## 6. 检索职责与边界

- **Voyage＋Lance**：主 semantic retrieval、Lance BM25 和排序；未改 pgvector，
  不重建或重新付费嵌入已有 canonical index。
- **PG**：原文和元数据持久化、稳定 source identity 去重、版本/checkpoint、
  小索引查找及批量原文回填。API 默认返回 raw，不返回英文 shadow。
- exact `source_identity` 或数字记录 ID 可直接通过 PG B-tree 查找。
  `previous_response_id` 等**内容标识符**仍由 native/Lance 检索，
  不是声称 PG 对 search_identifiers 建了精确内容索引。
- native 未就绪时不偷偷扫描 359 万行 PG 原文，也不自动重建 PG FTS。
  现有 `role/since/until` 等 native 不支持的过滤组合在关闭 PG FTS 后
  返回明确 `503 source_fts_unavailable`；本轮不伪称已补齐过滤能力。
